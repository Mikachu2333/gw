# WPS JS 版功能与验收

功能区沿用 Word/VSTO 版的“版面、公文标题、文字格式、插入、其他、关于”分组。
标题按钮可以直接从 1 开始编号，也可通过右侧下拉选择 1–20。

| 功能 | WPS JS 实现 |
| --- | --- |
| 页面设置 | 对话框设置五项边距、22 行×28 字网格和固定行距；逐节应用 A4，保留横向节 |
| 标题、正文 | 四级编号及大纲级别、正文首行缩进、二号字体选择；编号模板复用 |
| 字体与样式 | 十类字体设置；独立转换 NameAscii/NameOther/NameFarEast，保留其他原字体；字母/数字字体替换、七个公文样式刷新、着重号和隐藏 |
| 排版菜单 | 空白/空行/图形清理、移除超链接、断行重排、标点转换、文本框转文字、段前分页 |
| 公文部件 | 从原版 DOTX 提取的单行/联合发文机关、上下函线和装订线；原有格式保留 |
| 插入 | 红线、单/双行版记、日期、横页、符号、链接或嵌入公章 |
| 页码 | 居中、居右、外侧、光标处；跳过链接页脚，处理独立节及首页不同 |
| 副本 | PDF、DOC、逐页 PNG/JPG、图片型 PDF；图片在本地渲染，保留页面尺寸与方向，输出重名时自动编号 |
| 文档保护 | 只读保护/解除、打开/修改密码及清除密码；用户保存后写入文件 |
| 朗读 | 使用宿主浏览器的语音接口；不支持时禁用按钮 |
| 脚本工具 | 原版 42 项中 38 项可运行（含适配版），4 项未移植；另新增图片型 PDF，共 43 项目录；支持搜索、参数输入和最近使用 |
| 尚未移植 | PDF 合并、任意外部 VBA 执行、Excel 两项功能、图片转 PPT、外部扫描 PDF；自动排版细节仍有差异 |

脚本入口为“其他 → 脚本工具”。逐项范围和差异见 [VBA 移植对照表](VBA-PORTING.md)。
两种自动排版目前是主流程适配，不能视为原版全部规则的等价实现。
对照 `84d9734f5ce6` 的已修问题、完整功能对照及剩余限制见 [一致性审查与修复记录](PARITY-AUDIT-84d9734f5ce6.md)。
字体按钮保留原有粗体/斜体，配置启用时再加上；自定义半磅字号按原版取最近偶数，10.5 磅保留。
主“删除空行”优先处理选区，无选区时确认全文处理。外侧页码向内缩进一字符；带圈序号命令应用自动列表。
公文样式刷新时以 Normal 为基样式，并同步它的西文字体和段落对齐；正文按钮仍首行缩进两字符。
拆分/保存选区逐节复制分栏、镜像边距、装订线等页面设置；粘贴节数不符或属性复制失败时，保留新文档供手动检查。
自动排版两个版本分别采用原脚本署名位置表和三段留白；2026 版取消各节重新起号，并重建启用的独立首页/偶数页脚。
批处理跳过用户已经打开的文件，只关闭本次打开的文件；导出重名时自动编号，批量替换需确认覆盖保存。
脚本历史单独保存为用户主目录 `.gw_mika-script-history.json`，不随字体/页面设置恢复默认值而清空。

“副本 → 输出为图片 / 图片型 PDF”使用独立导出窗口：100/150/200/300/400/600 DPI，默认 200。
WPS 将当前文档导出到唯一临时 PDF，再用随包携带的 PDF.js 4.10.38 legacy 渲染，逐页保存或组装 PDF。
整个过程离线，不使用无响应的 `FileSaveAsPicture` 命令。图片型 PDF 每页只有 JPEG 图像，不保留原文字层、链接或书签。
取消会在当前页处理后停止，已输出的 PNG/JPG 保留，临时 PDF 在结束/失败时清理。
程序意外终止时可能留下系统临时目录中的 `gw_mika-render-*.pdf`，可在退出 WPS 后手动清理。
图片型 PDF 使用 JPEG 压缩，与无损 PNG 的清晰度和体积不同。
输出使用 WPS 专用 `writeAsBinaryString`，不把 ArrayBuffer 传给文本接口 `WriteFile`。
读取依次尝试 `ReadFileAsArrayBuffer`、`readAsBinaryString`、`ReadFile`；每次输出均校验完整字节，失败只清理本次新建的输出。
单页最多 4000 万像素（支持 A4 600 DPI），更大的纸张超限时会提示降低分辨率。

离线渲染器由 `tools/build-pdf-renderer.mjs` 生成到 `wps-js/vendor/pdfjs`（git 忽略），
`npm run build/dev/debug` 会先生成。运行时使用经典脚本、主线程 worker 和本机二进制字体/CMap 读取。
PDF.js 的 Apache-2.0 许可及字体/CMap 许可随 vendor 目录发布；渲染禁用动态代码求值。

页面设置和高级设置分别保存当前编辑的选项。“恢复默认值”先填入默认值，点击保存后生效。
行数、字数只接受 1–200 的整数；旧设置中的小数计数读取时回到默认的 22 行、28 字。
边距和行间距仍允许小数。数字输入被浏览器校验拦截时，诊断日志记录 `settings.invalid`。
设置文件位于用户主目录 `.gw_mika-settings.json`，同一 WPS 会话内通过 PluginStorage 即时共享。

宿主接口分为两层：文字操作通过 `app()` 取得 `WpsApplication()` / `Application`；
`ShowDialog`、`FileSystem`、`Env`、`PluginStorage`、`ApiEvent`、`ribbonUI` 和 `OAAssist`
通过 `gwHost` / `gwHostOwner` 从加载项根对象 `wps` / `window.Application` 取得。
`FileDialog` 是文字 API，仍从 `app()` 调用。新建文档事件名为 `DocumentNew`。
功能区 `GetImage` 按官方文字模板返回 `images/xxx.png` 相对路径；HTML 窗口使用绝对 URL。

## 出错时获取诊断信息

1. 安装新包，完全退出并重新打开 WPS。用临时文档重现问题，记下按钮名称和操作步骤。
2. 打开“公文准式 → 关于 → 诊断日志”，点击“刷新并保存”，再点击“复制日志”。
   将报告与复现步骤一起反馈；也可以提供窗口显示的 `.gw_mika-diagnostics.json` 文件。
   默认路径为用户主目录（Windows 通常为 `%USERPROFILE%`，Linux 为 `~`）。
3. 若页面设置窗口能打开但应用失败，窗口会显示具体接口步骤，例如
   `Sections.Item(2).PageSetup.CharsLine`，并自动保存日志。
4. 如果诊断窗口也打不开，按钮会尝试直接保存文件并提示路径。
   仍失败时，关闭错误提示后按 **Alt+F12** 打开加载项调试器，在 Console 执行
   `gwDiagnosticText()`，复制返回内容。快捷键不可用时，在 `wps-js` 目录运行
   `npm run debug`（官方 `wpsjs debug`），再按 Alt+F12；这是源码调试环境，离线公文部件插入需要安装版。
5. 图标问题请说明诊断窗口的三个预览图标与功能区图标是否分别正常。
   报告中的 `asset.browser.loaded` 只表示网页解码成功，不能证明原生功能区已显示成功。

修订标识为 `wps-api-20261110-6`，便于确认 WPS 加载的是新脚本。日志保留会话内最近 120 条记录，
点击诊断按钮或出现异常时覆盖导出文件。记录含版本、接口能力、按钮 ID、脚本路径和错误栈；
不主动读取文档正文、文件名、选中文字或密码。路径和宿主错误文本可能含本机用户名，反馈前可自行遮盖。

修复依据在仓库 `wps开发指南`：加载项 `Application 对象`、`Application.ShowDialog`、
`__文字事件__`、`FileSystem.WriteFile/ReadFile`，以及文字 API 的 `Application.FileDialog`、
`PageSetup.LayoutMode/CharsLine/LinesPage`。图标路径参照已安装的官方
`wpsjs/packages/@wps-jsapi/wps/js/ribbon.js` 模板。

开发时在 `wps-js` 下运行 `npm run build`。本地公文部件需要离线安装路径；HTTP 调试不支持插入这些文件。
原版模板修改后，在仓库根目录运行 `python tools/extract-wps-parts.py` 更新五个 DOCX。

自动检查在仓库根目录运行：

宿主验收请使用临时文档，并分别在 Windows、Linux WPS 上检查：

1. 安装后完全退出再打开 WPS。六个分组和 PNG 图标正常；四级标题均有 20 个编号选项。
2. 页面设置应用 37/35/28/26 毫米边距、24.7 毫米页脚和 22×28 网格；关闭网格后实际取消网格。
3. 选中部分文本清理空白，确认选区外内容不变；无选区时取消全文操作不应修改文档。
4. 标题从“五、”“（三）”“12．”“（20）”开始编号；改为正文后去掉编号并首行缩进两字符。
5. 三节文档中第二节链接到前节、第三节断开链接，启用首页不同；检查居中、居右、外侧页码及重复点击。
6. 带图片、表格和域的空段落清理后仍保留；插入五个公文部件、版记、横页及透明公章。
7. 修改字体设置、关闭窗口后排版，再重启 WPS 确认设置保留；缺少字体时按提示安装或更换。
8. 空文档、无打开文档、只读和受保护文档下检查控件状态；解除保护入口仍可使用。
9. PDF/DOC 副本包含刚保存的修改；取消保存对话框不应切换文件；以 `.doc` 为源文件时不能覆盖源文件。
10. 在页眉编辑状态执行页眉清理后保留原视图；插入公文部件时要求返回正文；异常后屏幕刷新正常。
11. 英文/数字的原字体为仿宋时，转换为仿宋_GB2312；同段其他字体保持原样。查看 `font.replace` 和 `font.availability` 日志。
12. 用临时文档验收脚本的选区边界、章条编号、图片、拆分、文件重名和取消；打印功能需另行人工确认打印机输出。

自动化宿主模型只验证调用契约及逻辑，不代表上述 WPS 图形界面验收已经完成。
`test-raster-export.mjs` 使用本机 Chrome（可用 `CHROME_PATH` 指定），验证真实 PDF 渲染、图像写入、页数/尺寸/旋转和无文字层；WPS 桥仍由文件替身模拟。
另检查 400/600 DPI 的实际图像尺寸；`test-raster-io.mjs` 模拟旧宿主文本专用写入、读取接口返回空值/抛错、损坏输出及 NUL/高位字节，防止仅凭接口返回值判断成功。
