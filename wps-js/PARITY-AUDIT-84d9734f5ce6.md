### F01 · P1 · 主“删除空行”按钮越过选区

- 当前：`js/ribbon.js:152` 固定调用 `gwDeleteEmptyLines(false)`；`js/textformat.js:35` 的这个分支固定取全文，也不确认无选区的全文操作。
- 基准：`Ribbon1.Format.cs / btnFormatDelEmptyLine_Click` 有选区时处理选中段落，仅无选区时确认处理全文。
- 复现：文档为 `外部\r\r选区\r\r末尾\r`，只选 `选区\r\r`，点击主“删除空行”。当前得到 `外部\r选区\r末尾\r`；选区外的空行也被删掉。
- 判断：内存宿主已复现。另有“删除空段落（选择范围）”入口不能代替主按钮原有的范围约定。应恢复自动识别选区与无选区确认，同时保留当前对图片、表格、域、最终段落的保护。

### F02 · P2 · 所有预设字体按钮额外清除粗体和斜体

- 当前：`js/util.js:99` 的 `setRangeFont` 无条件把未勾选的 `Bold/Italic` 写为 `0`，被正文、主标题、四级标题、版头、签发人、版记等共享。
- 基准：`Ribbon1.Fonts.cs / SetFont` 只在配置启用粗体/斜体时写入 `1`；未启用时保留选中文字现有的强调格式。
- 复现：选中粗体、斜体正文，使用默认设置点击“正文”。当前两项都变为普通；基准保留。首行缩进变为 2 字符是接受的新增行为。
- 判断：内存宿主已复现。这是除正文缩进以外的另一个行为变更。若产品确实要“按预设完整覆盖字体样式”，应明确说明；若要求基准兼容，应区分设置字体与显式清除强调。

### F03 · P2 · 外侧页码丢失一字符内缩

- 当前：`js/pagenum.js:27`、`:29` 将首行和右缩进都设为 `0`，外侧模式没有再设回。
- 基准：`Ribbon1.PageNumber.cs / PageNumberAligment(1)` 在 Word 与 WPS 分支都设置奇数页右缩进 `1` 字符、偶数页首行缩进 `1` 字符。
- 复现：插入外侧页码，检查奇数页 `CharacterUnitRightIndent` 与偶数页 `CharacterUnitFirstLineIndent`，当前均为 `0`，基准为 `1`。
- 判断：内存宿主已复现。宋体默认实际 14 pt 和 `— PAGE —` 文本形态一致，但位置不一致。独立节、首页页脚补全和跳过链接页脚是另外的改进，不需要回退。

### F04 · P2 · “转换数字为带圈序号”改变了功能类型

- 基准：`Ribbon1.Insert.cs / BtnSymbol_index_Click` 创建 `wdListNumberStyleNumberInCircle` 自动列表，以选中的数字作为 `StartAt`，并不替换该文本。

### F05 · P2 · 公文样式的西文字体和正文对齐被改写

### F06 · P2 · 拆分与保存选区的页面设置复制不完整

- 当前：`js/macro-files.js:19` 只复制方向、宽高、四边距、页眉页脚距离、网格模式和行/字数；`gwMacroWriteRange` 对整个输出文档应用这一份设置。
- 基准：按分节符拆分、按分页符拆分、保存选区脚本使用整个 `PageSetup` 赋值；至少未主动省略分栏、装订线、镜像页边距、垂直对齐等页面属性。
- 复现证据：输入 `Gutter=20, MirrorMargins=-1, VerticalAlignment=1, TextColumns.Count=2`，复制函数执行后目标仍为 `0,0,0,1`。跨节且页面几何不同的选区也没有逐节复制逻辑。
- 判断：**确定的是复制契约缺项**。完整节被粘贴时，部分属性可能恰好通过粘贴保留，不能断言所有拆分必定丢失；未包含节标记的片段、混合横竖页和多栏文档需要真实 WPS 验收。不能据当前实现宣称原版所有页面格式已对齐。

### F07 · P2 · 用所选文字命名会把句点后的标题截掉

- 当前：`js/macro-files.js:70` 把选中文字交给 `gwMacroBase`，后者先执行 `/\.[^.]+$/` 去扩展名。
- 基准：`用所选文字保存文件名.vba` 只去换行和部分非法路径字符，不把标题里的句点当成扩展名。
- 复现：选中 `关于方案v1.2的通知`，当前初始文件名变成 `关于方案v1.docx`。若标题有多个句点，则最后一个句点及其后的部分丢失。
- 判断：已复现 helper 的确定输出及调用路径。应把“源文件去扩展名”和“用户标题净化”分开。该入口固定输出 `.docx`，也比基准的另存为对话框格式选择少，见功能表。

### F08 · P2 · 自动排版 2026 没有恢复跨节连续页码

- 基准：`公文自动排版2026.vba / PageNumber` 显式设置 `RestartNumberingAtSection=False`，并将主页脚链接到前节。
- 复现：三页以上文档，后续独立节设置重新从 7 编号。当前该标志和起始值保持原样；另设后续节首页/奇偶页不同，其原首页和偶数页脚文本也保持原样。
- 判断：内存宿主确认遗漏了这些写入，最终显示页码仍需 WPS 分页验证。重新起号是与基准明确不同的规则；后续首页/偶数页脚的遗留是当前重建流程的完整性风险，基准本身也不是处理这些情况的完整范本。

### F09 · P2 · 自动排版落款复用了不对应的定位公式

- 当前：`js/macro-format.js:71` 日期右缩进 `5.9` 字符；`:85` 署名却使用独立“公文落款”脚本的 `2 cm + 字数差 × 0.75 cm / 2` 公式。
- 基准：普通“公文落款”脚本中日期和署名都以 `2 cm` 为基点；两个**自动排版**脚本分别有其自身的字数表、日期宽度调整和署名首行定位公式，不能把三个入口互换。
- 复现：`某某机关` + `2026年11月10日`，当前署名右缩进为约 `131.10 pt`，日期仍是 `5.9` 字符，且没有基准自动排版在署名前插入的三段留白。
- 判断：公式差异已经确认，实际相对中心还受字体度量影响。现有说明只强调复杂多落款未等价，容易掩盖普通单落款也不同。应分别实现经典版、2026 版规则，或者把单落款差异也明确列入适配范围。

### F10 · P3 · 自定义半磅字号的取整规则不等价

- 当前：`js/util.js:44` 使用 `Math.round`。
- 基准：`Ribbon1.cs / FormatFontSize` 使用 .NET `Math.Round` 的默认中点舍入。两边都特别保留 10.5 pt。
- 复现：`12.5 / 14.5 / 16.5`，基准为 `12 / 14 / 16`，当前为 `13 / 15 / 17`。已分别执行本机 .NET 和 JS 确认。
- 判断：默认 15.75、21.75、14.25 pt 都不受影响；高级设置允许的自定义字号受影响。“沿用原版字号取整规则”的说明目前不精确。

### F11 · P3 · 着重号/隐藏的非二值状态切换不同

- 当前：`js/commands.js:6` 统一用 JavaScript truthiness 切换所有字体属性。

- 复现：`EmphasisMark=1` 当前变 `0`，基准变 `4`；`Hidden=9999999` 当前变 `0`，基准变 `-1`。
- 判断：内存宿主已复现。现有纯开/关测试不覆盖这些状态；应对两个属性分别定义目标状态。

### F12 · P2 · 自动排版标题后仅一字正文没有恢复正文字体

## 两个自动排版脚本的适配边界

它们不是功能区“页面设置”的自动串联。原 VBA 本身采用 25.4/31.7 mm 等边距，而非功能区的37/35/28/26 mm；当前 JS 对这两套参数的区分正确，不应为了统一默认值而改错。

| 规则 | 已对应部分 | 仍不同或缺失部分 |
| --- | --- | --- |
| 页面 | 竖页上/下25.4、左/右31.7 mm；横页经典上/下25、2026上/下25.4 mm，左右25.4 mm；页眉15、页脚经典17.5/2026为15 mm | 完整页面环境、原模板样式重置未移植。 |
| 初始化 | 主文档域解除、编号转文字、软回车转段落、部分编号后空白清理、附表→附件、表格取消环绕并居中 | 缺“附”补“件”、2026发文字号六角括号修正、句末括号与句号换位、下划线占位符往返。 |
| 层级编号 | 四种前缀、层级计数及遇附件重置；经典三级四级仿宋/2026宋体的显式字体分支 | 2026相邻同级标题按正文/标题处理的判定、首句下划线、末尾标点处理、“第一，”“一是/一要”语义规则未等价。段前/段后13 pt被统一应用，基准部分正文式标题会归零。 |
| 正文 | 仿宋16 pt、两字符缩进、18 pt行距写入、取消网格对齐等 | 未 ClearFormatting/完整重置 Normal；旧的左右缩进、隐藏、下划线、缩放等并非全部清除。LineSpacingRule 与样式继承的最终效果需宿主检查。 |
| 主标题 | 开头连续段落识别、居中、22 pt | 经典版基准通过标题样式/模板控制并有未调用的 Xbs 函数；JS直接强制小标宋。基准插入的21/26 pt空段、经典1.15行距、2026副标题18 pt、短标题字距、主送机关样式、破折号终止条件等不完整。 |

| 页码 | 三页起插入、宋体14 pt、一字线居中 | 2026连续起号F08；经典原版只主处理首节，JS扩大到独立节。首页/奇偶页脚遗留仍需验收。 |
| 附件与表格 | “附件”段取消首行缩进并重置计数、表格行居中 | 附件清单重建、前后附件核对、跨节重排、表前表后微型空段、逐行挤排缺失。 |

因此，两个自动排版入口“适配版”的标签是必要的，但现有说明的“主流程”也不表示其简单输入已完全等价；F08/F09/F12需要明确修复或记录。

5. 页眉图片、多个文本框、链接图片、组合图形、跨页表格；检查清理范围、锚点、桌签边框/分页和图片PDF空白页。
